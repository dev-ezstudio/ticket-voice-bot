# 🤖 บอท Discord — ระบบตั๋วสนับสนุน + ห้องเสียงชั่วคราว

บอท Discord ภาษาไทยที่รวม **2 ระบบ** ไว้ในโปรเจกต์เดียว โดยแยกโค้ดออกจากกันชัดเจน ใช้ **Supabase (PostgreSQL)** เป็นฐานข้อมูลกลาง

> 💬 **ข้อความทั้งหมดแก้ได้จากไฟล์ `messages.json`** ไม่ต้องแตะโค้ด — ดู[หัวข้อที่ 12](#12-แก้ข้อความของบอท)
> 🎛️ **ห้องเสียงใช้ปุ่มกดล้วน** ไม่มีคำสั่งให้จำเลย — ดู[แผงควบคุม](#-แผงควบคุมแบบปุ่มกด-ไม่ต้องพิมพ์คำสั่ง)
> 📊 **มีเว็บ dashboard** ดูสถิติในเบราว์เซอร์ ล็อกอินด้วย Discord — ดู[หัวข้อที่ 13](#13-เว็บ-dashboard)

| ระบบ | ทำอะไร |
|------|--------|
| 🎫 **ระบบตั๋วสนับสนุน** | ผู้ใช้กดปุ่มเปิดห้องคุยส่วนตัวกับทีมงาน มีระบบรับเรื่อง ปิดตั๋ว บันทึกบทสนทนาเป็นไฟล์ และ **แผงควบคุม 3 หน้า** แยกตามสิทธิ์ (ผู้ใช้ / ทีมงาน / แอดมินใหญ่) |

## 2. สมัคร Supabase และรัน schema.sql

### 2.1 สร้างโปรเจกต์

1. เข้า [supabase.com](https://supabase.com) → **Start your project** → ล็อกอินด้วย GitHub หรืออีเมล
2. กด **New project**
3. กรอกข้อมูล:
   - **Name** — ชื่ออะไรก็ได้ เช่น `discord-bot`
   - **Database Password** — ตั้งรหัสไว้ (บอทไม่ได้ใช้ แต่เก็บไว้เผื่อต้องเข้าฐานข้อมูลตรงๆ)
   - **Region** — เลือก **Southeast Asia (Singapore)** จะเร็วที่สุดสำหรับคนไทย
4. กด **Create new project** แล้วรอประมาณ 2 นาที

### 2.2 รัน schema.sql (สร้างตารางของทั้ง 2 ระบบ)

เลือกทำ **วิธีใดวิธีหนึ่ง**

#### วิธี A — ให้สคริปต์รันให้อัตโนมัติ (แนะนำ)

1. เอา connection string: Supabase Dashboard → ปุ่ม **Connect** ด้านบน → แท็บ **Connection string** → เลือกแบบ **Session pooler** → คัดลอก URI
2. ใส่ใน `.env` แล้วแทน `[YOUR-PASSWORD]` ด้วยรหัสฐานข้อมูลที่ตั้งไว้ตอนสร้างโปรเจกต์:

   ```env
   DATABASE_URL=postgresql://postgres.abcdefgh:รหัสของคุณ@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
   ```

3. รัน:

   ```bash
   npm install
   npm run setup-db
   ```

สคริปต์จะรัน `schema.sql` ให้ แล้วตรวจผลลัพธ์ว่าครบไหม:

```
🗄️  ติดตั้งตารางฐานข้อมูลขึ้น Supabase

📄 ไฟล์      : schema.sql (11.4 KB)
🎯 ปลายทาง   : postgresql://postgres.abcdefgh:••••••@aws-0-...:5432/postgres

🔌 กำลังเชื่อมต่อฐานข้อมูล...
   ✅ เชื่อมต่อสำเร็จ

⚙️  กำลังรัน schema.sql...
   ✅ รันสำเร็จ

🔍 ตรวจสอบผลลัพธ์...

   ตาราง:
     ✅ blocked_users
     ✅ temp_channels
     ✅ ticket_settings
     ✅ tickets
     ✅ voice_settings

   ฟังก์ชัน:
     ✅ next_ticket_number()
     ✅ set_updated_at()

   Row Level Security:
     ✅ เปิดครบทุกตาราง (5 ตาราง)

   Index สำคัญ:
     ✅ idx_tickets_one_open_per_user (กัน 1 คนเปิดตั๋วซ้อน)

  ✅ ติดตั้งฐานข้อมูลสำเร็จครบทั้ง 2 ระบบ
```

> ⚠️ **ถ้ารหัสผ่านมีอักขระพิเศษ** (`@ : / ? #`) ต้อง URL-encode ก่อน เช่น `@` → `%40`, `#` → `%23`
> ⚠️ ถ้าเน็ตของคุณเป็น IPv4 อย่างเดียว **ต้องใช้ Session pooler** ไม่ใช่ Direct connection

#### วิธี B — ทำมือผ่านเว็บ

1. ในหน้าโปรเจกต์ กดเมนู **SQL Editor** (ไอคอนซ้ายมือ)
2. กด **+ New query**
3. เปิดไฟล์ `schema.sql` ในโปรเจกต์นี้ **คัดลอกทั้งไฟล์** ไปวางในช่อง
4. กด **Run** (หรือ `Ctrl + Enter`)

ถ้าสำเร็จจะเห็นตาราง 5 แถวขึ้นมาด้านล่าง:

```
ตารางที่สร้างสำเร็จ
------------------
blocked_users
temp_channels
ticket_settings
tickets
voice_settings
```

> 💡 ไฟล์ `schema.sql` รันซ้ำได้ไม่พัง (ใช้ `IF NOT EXISTS` ทุกคำสั่ง) ถ้าไม่แน่ใจว่ารันไปแล้วหรือยัง รันอีกครั้งได้เลย ข้อมูลเดิมไม่หาย

### 2.3 เอาค่า SUPABASE_URL และ SUPABASE_KEY

1. กดเมนู **Project Settings** (ไอคอนฟันเฟือง มุมซ้ายล่าง)
2. **SUPABASE_URL** — เมนู **Data API** → คัดลอกช่อง **Project URL**
   - หน้าตาแบบนี้: `https://abcdefghijklmnop.supabase.co`
3. **SUPABASE_KEY** — เมนู **API Keys** → คัดลอก **key ฝั่ง secret**

   Supabase มี key 2 ระบบ ขึ้นกับว่าโปรเจกต์สร้างเมื่อไหร่ — **ใช้ได้ทั้งคู่ ไม่ต้องแก้โค้ด**:

   | ระบบ key | ตัวที่บอทต้องใช้ | ตัวที่**ห้าม**ใช้ |
   |----------|------------------|-------------------|
   | แบบใหม่ | `sb_secret_...` | `sb_publishable_...` |
   | แบบเดิม | `service_role` (ขึ้นต้น `eyJ...`) | `anon` |

   - ⚠️ **ต้องใช้ตัวฝั่ง secret** เพราะตารางเปิด RLS (Row Level Security) ไว้ ถ้าใช้ `publishable` / `anon` บอทจะอ่านเขียนข้อมูลไม่ได้เลย
   - ⚠️ key นี้มีสิทธิ์เต็ม **ห้ามเผยแพร่** และห้าม commit ไฟล์ `.env` ขึ้น git
   - 💡 ถ้า key เคยหลุดไปที่ไหน ให้ **rotate** ทันทีที่ Dashboard → API Keys

## 3. สร้างบอทและเอา Token

1. เข้า [Discord Developer Portal](https://discord.com/developers/applications) → **New Application** → ตั้งชื่อ → **Create**

2. **เอา CLIENT_ID** — อยู่หน้า **General Information** → คัดลอก **Application ID**

3. **เอา TOKEN** — เมนู **Bot** → กด **Reset Token** → **Yes, do it!** → คัดลอก token ที่ขึ้นมา
   - ⚠️ token แสดงครั้งเดียว ถ้าปิดหน้าไปต้อง reset ใหม่

4. **เปิด Privileged Intents** (ขั้นตอนนี้สำคัญ ถ้าไม่ทำบอทจะรันไม่ได้)

   ยังอยู่ในเมนู **Bot** เลื่อนลงไปหา **Privileged Gateway Intents** แล้วเปิด **2 อัน**:

   | Intent | เปิด | ระบบไหนใช้ |
   |--------|------|-----------|
   | PRESENCE INTENT | ❌ ไม่ต้อง | – |
   | **SERVER MEMBERS INTENT** | ✅ **เปิด** | ทั้ง 2 ระบบ (อ่านข้อมูลสมาชิกและยศ) |
   | **MESSAGE CONTENT INTENT** | ✅ **เปิด** | ระบบตั๋ว (อ่านข้อความเพื่อทำ transcript) |

   กด **Save Changes** ด้านล่าง

## 4. ตั้งค่าไฟล์ .env

คัดลอกไฟล์ตัวอย่างเป็นไฟล์จริง:

```bash
# Windows (Command Prompt)
copy .env.example .env

# Windows (PowerShell)
Copy-Item .env.example .env

# Mac / Linux
cp .env.example .env
```

เปิดไฟล์ `.env` ด้วย Notepad หรือ VS Code แล้วกรอก **4 ค่า**:

```env
TOKEN=MTIzNDU2Nzg5MDEyMzQ1Njc4.Abcdef.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
CLIENT_ID=1439869220153462834
SUPABASE_URL=https://abcdefghijklmnop.supabase.co
SUPABASE_KEY=sb_secret_xxxxxxxxxxxxxxxxxxxx
```

| ค่า | เอามาจากไหน |
|-----|-------------|
| `TOKEN` | Developer Portal → Bot → Reset Token |
| `CLIENT_ID` | Developer Portal → General Information → Application ID |
| `SUPABASE_URL` | Supabase → Project Settings → Data API → Project URL |
| `SUPABASE_KEY` | Supabase → Project Settings → API Keys → **`sb_secret_...`** (หรือ **`service_role`** ถ้าเป็นโปรเจกต์แบบเดิม) |

### ค่าเพิ่มเติม (ไม่บังคับ)

```env
GUILD_ID=1429554218662105101
```

ใส่ `GUILD_ID` ตอนพัฒนา จะทำให้ slash command **ใช้ได้ทันที** ในเซิร์ฟเวอร์นั้น
ถ้าเว้นว่าง คำสั่งจะลงทะเบียนแบบ global (ใช้ได้ทุกเซิร์ฟเวอร์ แต่รออัปเดตถึง 1 ชั่วโมง)

**วิธีเอา Guild ID:** ใน Discord เปิด **User Settings → Advanced → Developer Mode** แล้วคลิกขวาที่ชื่อเซิร์ฟเวอร์ → **Copy Server ID**

## 5. เชิญบอทเข้าเซิร์ฟเวอร์

### วิธีที่ 1 — ใช้ลิงก์สำเร็จ (ง่ายสุด)

เอา `CLIENT_ID` ของคุณไปแทนใน URL นี้แล้วเปิดในเบราว์เซอร์:

```
https://discord.com/api/oauth2/authorize?client_id=CLIENT_ID_ของคุณ&permissions=286346256&scope=bot%20applications.commands
```

### วิธีที่ 2 — สร้างลิงก์เอง

Developer Portal → เมนู **OAuth2** → **URL Generator**

**SCOPES** ติ๊ก 2 อัน:
- ✅ `bot`
- ✅ `applications.commands` ← **ถ้าไม่ติ๊ก slash command จะไม่ขึ้น**

**BOT PERMISSIONS** ติ๊กตามนี้:

| Permission | ชื่อไทย | ระบบไหนใช้ | ใช้ทำอะไร |
|-----------|--------|-----------|-----------|
| **Manage Channels** | จัดการห้อง | ทั้ง 2 | สร้าง/ลบห้องตั๋วและห้องเสียง |
| **Manage Roles** | จัดการยศ | ตั๋ว | ตั้งสิทธิ์ให้เห็นห้องตั๋วเฉพาะคนที่เกี่ยวข้อง |
| **Move Members** | ย้ายสมาชิก | ห้องเสียง | ย้ายคนเข้าห้องใหม่ / เตะออกจากห้อง |
| **Connect** | เข้าห้องเสียง | ห้องเสียง | มองเห็นและจัดการห้องเสียง |
| **View Channels** | มองเห็นห้อง | ทั้ง 2 | เห็นห้องที่ต้องจัดการ |
| **Send Messages** | ส่งข้อความ | ทั้ง 2 | ส่ง embed และข้อความแจ้งเตือน |
| **Embed Links** | ฝัง Embed | ทั้ง 2 | แสดง embed สวยงาม |
| **Attach Files** | แนบไฟล์ | ตั๋ว | ส่งไฟล์ transcript |
| **Read Message History** | อ่านประวัติข้อความ | ตั๋ว | อ่านข้อความเก่าเพื่อทำ transcript |
| **Manage Messages** | จัดการข้อความ | ตั๋ว | ปักหมุด embed ต้อนรับ |

คัดลอก **GENERATED URL** ด้านล่างไปเปิดในเบราว์เซอร์ → เลือกเซิร์ฟเวอร์ → **Authorize**

> ⚠️ **สำคัญ:** หลังเชิญบอทเข้ามา ไปที่ **Server Settings → Roles** แล้วลาก **ยศของบอท** ขึ้นไปให้อยู่**สูงกว่า**ยศทีมงาน ไม่งั้นบอทจะจัดการสิทธิ์บางอย่างไม่ได้

### คำสั่ง npm ทั้งหมด

| คำสั่ง | ทำอะไร | ต้องรันเมื่อไหร่ |
|--------|--------|-----------------|
| `npm install` | ติดตั้ง package | ครั้งแรกเท่านั้น |
| `npm run setup-db` | รัน `schema.sql` ขึ้น Supabase | ครั้งแรก (ถ้าไม่ได้ทำมือใน SQL Editor) |
| `npm run deploy` | ลงทะเบียน slash command | ครั้งแรก + เมื่อแก้ชื่อ/ตัวเลือกคำสั่ง |
| `npm start` | รันบอท | ทุกครั้งที่จะใช้งาน |
| `npm run dashboard` | เปิดเว็บ dashboard | เมื่อต้องการดูข้อมูลในเบราว์เซอร์ |
| `npm run check` | เช็ค syntax error | เมื่อแก้โค้ดแล้วอยากเช็คก่อนรัน |

> 💡 แก้แต่ **logic ข้างในคำสั่ง** ไม่ต้องรัน `npm run deploy` ใหม่ — แค่รีสตาร์ทบอทพอ

## 7. ตั้งค่าระบบตั๋ว

### เตรียมของก่อน (ทำใน Discord)

1. **สร้างยศทีมงาน** — Server Settings → Roles → Create Role → ตั้งชื่อเช่น `ทีมงาน` หรือ `Support`
   แล้วมอบยศนี้ให้คนที่จะดูแลตั๋ว
2. **สร้าง Category** — คลิกขวาที่พื้นที่ว่างในรายการห้อง → Create Category → ตั้งชื่อเช่น `🎫 ตั๋วสนับสนุน`
3. **เตรียมห้องข้อความ** — ห้องที่จะวางปุ่มเปิดตั๋ว เช่น `#ศูนย์ช่วยเหลือ` (ห้องที่ทุกคนเห็นได้)

**ถ้าต้องการแผงควบคุมทีมงาน/แอดมิน (ไม่บังคับ)** เตรียมเพิ่ม:

4. **ห้องทีมงาน** เช่น `#staff-only` — ควร**ซ่อนจาก @everyone**
5. **ห้องแอดมินใหญ่** เช่น `#admin-only` — ควรซ่อนจาก @everyone
6. **ยศแอดมินใหญ่** เช่น `@หัวหน้าทีม` — ไม่สร้างก็ได้ ระบบจะใช้สิทธิ์ **Administrator** ของ Discord แทน

**แบบสั้น** (แค่หน้าเปิดตั๋ว — ใช้งานได้ครบ):

```
/setup-ticket ห้องเปิดตั๋ว:#ศูนย์ช่วยเหลือ หมวดห้องตั๋ว:🎫 ตั๋วสนับสนุน ยศทีมงาน:@ทีมงาน
```

**แบบเต็ม** (ครบ 3 หน้า):

```
/setup-ticket ห้องเปิดตั๋ว:#ศูนย์ช่วยเหลือ หมวดห้องตั๋ว:🎫 ตั๋วสนับสนุน ยศทีมงาน:@ทีมงาน ห้องทีมงาน:#staff-only ห้องแอดมินใหญ่:#admin-only ยศแอดมินใหญ่:@หัวหน้าทีม
```

| ตัวเลือก | บังคับ | ใส่อะไร |
|---------|:------:|--------|
| `ห้องเปิดตั๋ว` | ✅ | **หน้าที่ 1** — ห้องที่วางปุ่ม "📩 เปิดตั๋ว" ให้ทุกคนเห็น |
| `หมวดห้องตั๋ว` | ✅ | Category ที่ห้องตั๋วจะถูกสร้างเข้าไป |
| `ยศทีมงาน` | ✅ | ยศที่เห็นห้องตั๋วและกดรับเรื่องได้ |
| `ห้องทีมงาน` | – | **หน้าที่ 2** — ห้องวางแผงควบคุมทีมงาน |
| `ห้องแอดมินใหญ่` | – | **หน้าที่ 3** — ห้องวางแผงควบคุมแอดมินใหญ่ |
| `ยศแอดมินใหญ่` | – | ยศที่กดปุ่มหน้าแอดมินได้ (ไม่ระบุ = ใช้ Administrator) |

บอทจะส่ง embed พร้อมปุ่มไปที่ห้องที่ระบุทันที และบันทึกการตั้งค่าลง Supabase

> 💡 **ตั้งซ้ำได้** — รันคำสั่งใหม่ได้เลย ค่าเดิมจะถูกทับ (เลขตั๋วไม่รีเซ็ต)
> 💡 **ตั้งเพิ่มทีหลังได้** — ถ้าครั้งแรกไม่ได้ใส่ห้องทีมงาน มาใส่เพิ่มภายหลังได้ ค่าเดิมที่ไม่ได้ระบุจะไม่หาย

> ⚠️ ทุกปุ่มตอบแบบ **ephemeral** (เห็นคนเดียว) ห้องแผงควบคุมจึงไม่รกด้วยผลลัพธ์

| 3️⃣ ทีมงานกด **🙋 รับเรื่อง** | ระบบบันทึกว่าใครดูแล และ embed อัปเดตสถานะทันที |

### หลักการแยกระบบ

โปรเจกต์นี้ออกแบบให้ **แก้ระบบหนึ่งไม่กระทบอีกระบบ**:

| กฎ | ผลที่ได้ |
|----|---------|
| โค้ด `ticket/` ไม่ import `voice/` และกลับกัน | แก้ระบบตั๋วแล้วระบบห้องเสียงไม่พัง |
| แต่ละระบบมี `repo.js` ของตัวเอง แตะเฉพาะตารางของตัวเอง | เปลี่ยนโครงสร้างตารางระบบหนึ่ง ไม่ต้องแก้อีกระบบ |
| `customId` ของปุ่มขึ้นต้นด้วย `ticket:` / `voice:` | เพิ่มปุ่มระบบอื่นในอนาคตไม่ชนกัน |
| `supabase.js`, `lib/reply.js`, `lib/discordUtils.js` เป็นส่วนกลาง ไม่มี logic ของระบบใด | ใช้ร่วมกันได้โดยไม่ผูกกัน |
| ตัวโหลดใน `index.js` วนอ่านโฟลเดอร์เอง | เพิ่มคำสั่ง/event ใหม่แค่วางไฟล์ ไม่ต้องแก้ `index.js` |

**อยากเพิ่มระบบที่ 3?** สร้าง `commands/<ระบบใหม่>/`, `events/<ระบบใหม่>/`, `lib/<ระบบใหม่>/` แล้วเพิ่มตารางใน `schema.sql` — ไม่ต้องแตะโค้ดของ 2 ระบบเดิมเลย

| `staff_role_id` | TEXT | ยศทีมงาน |
| `admin_role_id` | TEXT | ยศแอดมินใหญ่ (NULL = ใช้ Administrator ของ Discord) |
| `admin_panel_channel_id` | TEXT | ห้องหน้าทีมงาน |

| `ticket_counter` | INTEGER | เลขรันนิ่งของตั๋ว |

**`tickets`** — ตั๋วแต่ละใบ

| คอลัมน์ | ชนิด | ความหมาย |
|---------|------|----------|
| `channel_id` 🔑 | TEXT | ID ห้องตั๋ว |
| `guild_id` | TEXT | ID เซิร์ฟเวอร์ |
| `user_id` | TEXT | ผู้เปิดตั๋ว |
| `user_tag` | TEXT | ชื่อผู้ใช้ตอนเปิด (เก็บเผื่อออกจากเซิร์ฟเวอร์) |

| `status` | TEXT | `open` หรือ `closed` |

### ระบบห้องเสียง

**`voice_settings`** — ตั้งค่า 1 แถวต่อ 1 เซิร์ฟเวอร์

| คอลัมน์ | ชนิด | ความหมาย |
|---------|------|----------|
| `guild_id` 🔑 | TEXT | ID เซิร์ฟเวอร์ |
| `creator_channel_id` | TEXT | ห้อง "➕ สร้างห้องของคุณ" |
| `category_id` | TEXT | Category ห้องเสียงชั่วคราว |

**`temp_channels`** — ห้องเสียงที่ยังมีอยู่

| คอลัมน์ | ชนิด | ความหมาย |
|---------|------|----------|
| `channel_id` 🔑 | TEXT | ID ห้องเสียง |
| `guild_id` | TEXT | ID เซิร์ฟเวอร์ |
| `owner_id` | TEXT | เจ้าของห้องปัจจุบัน |
| `name` | TEXT | ชื่อห้องล่าสุด |
| `is_locked` | BOOLEAN | ล็อกอยู่ไหม |
| `user_limit` | INTEGER | จำกัดกี่คน (0 = ไม่จำกัด) |
| `created_at` | TIMESTAMPTZ | เวลาสร้างห้อง |

**`blocked_users`** — ผู้ถูกบล็อกจากห้อง

| คอลัมน์ | ชนิด | ความหมาย |
|---------|------|----------|
| `channel_id` 🔑 | TEXT | ID ห้อง (ผูกกับ `temp_channels` แบบ CASCADE) |
| `blocked_user_id` 🔑 | TEXT | ผู้ถูกบล็อก |
| `blocked_by` | TEXT | ใครสั่งบล็อก |

> 💡 `ON DELETE CASCADE` ทำให้ห้องหาย → รายการบล็อกหายตามอัตโนมัติ ไม่ต้องเก็บกวาดเอง

### หมายเหตุการออกแบบ

- **ID เก็บเป็น `TEXT` ไม่ใช่ `BIGINT`** เพราะ Discord snowflake เป็นเลข 64 bit แต่ JavaScript number ปลอดภัยแค่ 2^53
- **ชื่อคอลัมน์เป็น `snake_case`** ตามธรรมเนียม PostgreSQL — โค้ดฝั่ง JS แปลงเป็น `camelCase` ให้แล้วใน `repo.js`
- **RLS เปิดไว้ทุกตารางแต่ไม่มี policy** = ปิดตายสำหรับ key ฝั่ง publishable/anon ถ้า key นั้นรั่วก็อ่านข้อมูลไม่ได้ (บอทใช้ key ฝั่ง secret ซึ่ง bypass RLS)
- **`next_ticket_number()`** เป็น SQL function เพื่อเพิ่มเลขตั๋วแบบ atomic กัน race condition ตอนหลายคนกดเปิดตั๋วพร้อมกัน
- **`idx_tickets_one_open_per_user`** เป็น partial unique index บังคับ 1 คน 1 ตั๋วเปิดต่อเซิร์ฟเวอร์ที่ระดับฐานข้อมูล (ไม่พึ่งโค้ดอย่างเดียว)

## 12. แก้ข้อความของบอท

ข้อความทั้งหมดของบอท (**230 คีย์**) อยู่ในไฟล์ `messages.json` แก้ได้เลยโดยไม่ต้องแตะโค้ด

### วิธีแก้

1. เปิดไฟล์ `messages.json` ด้วย Notepad หรือ VS Code
2. หาข้อความที่ต้องการแก้ แล้วแก้เลย
3. บันทึกไฟล์ แล้ว **รีสตาร์ทบอท** (ปิดแล้วเปิด `start-bot.bat` ใหม่)

### ตัวอย่าง

**เปลี่ยนหัวข้อ panel ตั๋ว:**

```json
"ticket": {
  "panel": {
    "title": "🎫 แจ้งปัญหา / สอบถาม",
    "buttonLabel": "แจ้งปัญหา",
    "buttonEmoji": "📮"
  }
}
```

**เปลี่ยนชื่อห้องเสียงที่สร้างใหม่:**

```json
"voice": {
  "roomName": "🎮 ห้องเกมของ {displayName}"
}
```

**เปลี่ยนชื่อ category และห้องสร้างห้อง:**

```json
"voice": {
  "setup": {
    "categoryName": "🎧 ห้องคุย",
    "creatorChannelName": "➕ กดสร้างห้อง",
    "guideChannelName": "📖 วิธีใช้"
  }
}
```

> ⚠️ ถ้าเปลี่ยนชื่อพวกนี้หลังรัน `/setup-voice` ไปแล้ว ต้องรัน `/setup-voice` อีกครั้ง หรือเปลี่ยนชื่อห้องเดิมใน Discord เอง

### กฎที่ต้องรู้

| กฎ | รายละเอียด |
|----|-----------|
| **คีย์ที่ขึ้นต้นด้วย `_`** | เป็นคำอธิบาย บอทไม่ได้ใช้ — ลบทิ้งได้ |
| **`[ ... ]` คือหลายบรรทัด** | แต่ละรายการใน array = 1 บรรทัด |
| **`{ชื่อตัวแปร}`** | จะถูกแทนด้วยค่าจริงตอนใช้งาน — **ห้ามแปลชื่อตัวแปร** |
| **ลบคีย์ออกได้** | บอทจะใช้ค่าเริ่มต้นของคีย์นั้นแทน ไม่พัง |
| **JSON เสียก็ไม่พัง** | บอทจะเตือนใน console แล้วใช้ค่าเริ่มต้นทั้งหมด |

ตรวจไฟล์ก่อนใช้ได้ที่ [jsonlint.com](https://jsonlint.com)

### ตัวแปรที่ใช้ได้

แต่ละกลุ่มมีคีย์ `_ตัวแปรที่ใช้ได้` บอกไว้ในไฟล์แล้ว สรุปตัวที่ใช้บ่อย:

| ตัวแปร | ความหมาย | ใช้ในกลุ่ม |
|--------|---------|-----------|
| `{ticketNumber}` | เลขตั๋ว | ticket |
| `{userMention}` | แท็กผู้เปิดตั๋ว | ticket |
| `{staffRoleMention}` | แท็กยศทีมงาน | ticket |
| `{staffMention}` | แท็กทีมงานที่รับเรื่อง | ticket |
| `{channelMention}` | ลิงก์ห้อง | ticket |
| `{guildName}` | ชื่อเซิร์ฟเวอร์ | ticket |
| `{displayName}` | ชื่อที่แสดงของผู้ใช้ | voice |
| `{ownerMention}` | แท็กเจ้าของห้อง | voice |
| `{targetMention}` | แท็กคนที่ถูกกระทำ | voice |
| `{creatorChannelName}` | ชื่อห้องสร้างห้อง | voice |
| `{count}` `{limit}` | จำนวนคน / ขีดจำกัด | voice |

### ค่าที่ไม่ใช่ข้อความ (ตั้งพฤติกรรมบอท)

| คีย์ | ความหมาย | ช่วงที่ใช้ได้ | ค่าเริ่มต้น |
|------|---------|-------------|-----------|
| `ticket.closing.deleteDelaySeconds` | หน่วงกี่วินาทีก่อนลบห้องตั๋ว | 1-60 | 5 |
| `voice.settings.createCooldownSeconds` | เว้นกี่วินาทีระหว่างสร้างห้อง 2 ครั้ง | 0-300 (0 = ไม่จำกัด) | 10 |
| `common.presence.type` | สถานะบอท | `playing` `watching` `listening` `competing` | watching |
| `common.presence.text` | ข้อความสถานะ | ข้อความอะไรก็ได้ | ระบบตั๋ว & ห้องเสียง |
| `ticket.panel.color` | สี embed panel | `success` `error` `warning` `info` `neutral` | info |

> 💡 ถ้าใส่ค่าเกินช่วง บอทจะปรับให้อยู่ในช่วงและเตือนใน console — ไม่พัง

## 13. เว็บ Dashboard

หน้าเว็บสำหรับดูข้อมูลระบบตั๋วและห้องเสียง เปิดในเบราว์เซอร์ — **แยก process จากบอท** ปิด dashboard บอทยังทำงานปกติ

> 🔧 **ตั้งค่าบอทได้จากเว็บ** (หน้าตั้งค่า) — เลือกห้องจาก dropdown ที่แสดง **ทุกห้อง** ไม่เหมือนรายการเลือกห้องของ Discord ที่แสดงไม่หมด
> 🔒 ข้อมูลตั๋วและห้องเสียงเป็น **อ่านเท่านั้น** — ปิดตั๋วยังต้องทำจากปุ่มในห้องตั๋ว (เพราะต้องสร้าง transcript ก่อนลบห้อง)

### มีหน้าอะไร

| หน้า | ใครดูได้ | มีอะไร |
|------|---------|--------|
| **ภาพรวม** | ทีมงาน + แอดมิน | การ์ดสถิติ 6 ใบ · กราฟตั๋วต่อวัน 14 วัน · อันดับทีมงาน · ตั๋วที่รอนานสุด · ตั๋วล่าสุด |
| **ตั๋ว** | ทีมงาน + แอดมิน | รายการตั๋วทั้งหมด กรองตามสถานะ แบ่งหน้า |
| **ห้องเสียง** | ทีมงาน + แอดมิน | ห้องที่ใช้งานอยู่ · เจ้าของ · สถานะล็อก |
| **ตั้งค่า** | **แอดมินใหญ่เท่านั้น** | **แก้การตั้งค่าบอทได้** — ย้ายห้องเปิดตั๋ว เปลี่ยนหมวด/ยศ ตั้งห้องแผง |

**สถิติที่ dashboard คำนวณให้ (บอทไม่มี):**
- **เวลาตอบเฉลี่ย** — ตั้งแต่เปิดตั๋วถึงทีมงานกดรับเรื่อง
- **เวลาปิดเฉลี่ย** — ตั้งแต่เปิดถึงปิด
- **กราฟตั๋วต่อวัน** — เห็นแนวโน้ม 14 วันล่าสุด

### หน้าตั้งค่า — แก้อะไรได้

**แอดมินใหญ่เท่านั้น** · เลือกจาก dropdown แล้วกดบันทึก

| ค่า | ทำอะไร |
|-----|--------|
| **ห้องเปิดตั๋ว** | บอท**ส่งปุ่มเปิดตั๋วไปห้องใหม่ + ลบใบเก่า**ให้ ไม่ต้องรัน `/setup-ticket` |
| **หมวดห้องตั๋ว** | เปลี่ยนหมวดที่ห้องตั๋วใหม่จะไปอยู่ (ห้องตั๋วเดิมไม่ย้าย) |
| **ยศทีมงาน** | เปลี่ยนยศที่เห็นห้องตั๋วและกดรับเรื่องได้ |
| **ยศแอดมินใหญ่** | เปลี่ยน หรือเลือก "ใช้สิทธิ์ Administrator" |
| **ห้องแผงทีมงาน** | ตั้ง / ย้าย / ถอด แผง 4 ปุ่มของทีมงาน |
| **ห้องแผงแอดมินใหญ่** | ตั้ง / ย้าย / ถอด แผง 5 ปุ่ม — **เป็นปลายทางไฟล์ `.txt` ด้วย** |
| **ห้องสร้างห้อง** (เสียง) | เปลี่ยนห้องที่เข้าแล้วได้ห้องส่วนตัว |

> 💡 **ทำไม dropdown ในเว็บดีกว่า** — รายการเลือกห้องของ Discord ไม่แสดงทุกห้อง ต้องเลื่อนหรือพิมพ์ค้นหา
> ส่วน dropdown ในเว็บแสดง**ครบทุกห้อง** เรียงตามที่เห็นใน Discord (เซิร์ฟเวอร์คุณ 21 ห้องข้อความ · 24 ยศ)

**บอทย้าย panel จริงให้ ไม่ใช่แค่แก้ฐานข้อมูล** — ลำดับที่ใช้:

1. ส่ง panel ใบใหม่ไปห้องใหม่ (ถ้าพลาด ยังไม่มีอะไรเปลี่ยน)
2. บันทึกลงฐานข้อมูล (ถ้าพลาด ลบ panel ที่เพิ่งส่ง)
3. ลบ panel ใบเก่า

จึงไม่มีทางเหลือปุ่มลอยอยู่ 2 ห้อง หรือฐานข้อมูลชี้ไปห้องที่ไม่มี panel

**แก้จากที่นี่ไม่ได้:** ข้อความบอท (แก้ที่ `messages.json`) · เลขตั๋ว (เดินขึ้นเอง) · ปิดตั๋ว (ต้องทำจากปุ่มในห้องตั๋ว)

### เปิดใช้แบบไม่ต้องล็อกอิน (ทดสอบในเครื่อง)

ถ้าอยากลองดูก่อนโดยไม่ต้องตั้ง OAuth ใส่บรรทัดนี้ใน `.env`:

```env
DASHBOARD_AUTH=off
```

แล้วเปิดได้เลย — ไม่ต้องมี `CLIENT_SECRET`

```bash
npm run dashboard
```

> 🔴 **โหมดนี้ไม่มีการป้องกันเลย** — ใครเปิด URL ได้ก็เห็นข้อมูลทั้งหมด (ชื่อสมาชิกที่เปิดตั๋ว, ใครรับเรื่อง, การตั้งค่าระบบ)
>
> ใช้ได้เฉพาะตอนรันบนเครื่องตัวเอง (`localhost`) ซึ่งคนอื่นเข้าไม่ถึง
> **ห้ามใช้ตอนเปิดออกอินเทอร์เน็ต** — ข้อมูลสมาชิกจะรั่วทันที

บอทเตือนให้ 2 ที่กันลืม: แถบสีแดงบนหัวเว็บ และข้อความตอนเปิด dashboard

**เปิดล็อกอินกลับ:** ลบบรรทัด `DASHBOARD_AUTH=off` (หรือเปลี่ยนเป็นค่าอื่น) แล้วทำตามหัวข้อถัดไป

### ตั้งค่าครั้งแรก

**1. เอา Client Secret**

Discord Developer Portal → เลือกแอป → **OAuth2** → **Client Secret** → **Reset Secret** → คัดลอก

**2. ตั้ง Redirect URI** (หน้าเดียวกัน)

**OAuth2** → **Redirects** → **Add Redirect** → ใส่:

```
http://localhost:3210/auth/callback
```

> ⚠️ ต้องตรงกับ `DASHBOARD_URL` ใน `.env` เป๊ะๆ — ถ้าไม่ตรง Discord จะปฏิเสธการล็อกอิน

**3. กรอกใน `.env`**

```env
CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
DASHBOARD_PORT=3210
DASHBOARD_URL=http://localhost:3210
SESSION_SECRET=<ข้อความสุ่มยาวๆ>

# ลบบรรทัดนี้ถ้าต้องการเปิดล็อกอิน
DASHBOARD_AUTH=off
```

สร้าง `SESSION_SECRET` ได้ด้วย:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> 💡 ถ้าไม่ตั้ง `SESSION_SECRET` ระบบสุ่มให้ชั่วคราว — ผลคือทุกคนต้องล็อกอินใหม่ทุกครั้งที่รีสตาร์ท dashboard

**4. เปิด**

```bash
npm run dashboard
```

หรือดับเบิลคลิก **`start-dashboard.bat`**

แล้วเปิดเบราว์เซอร์ไปที่ **http://localhost:3210**

### ใครเข้าได้

ใช้กฎเดียวกับปุ่มในบอท:

| ระดับ | เงื่อนไข | เข้าได้ |
|-------|---------|--------|
| **แอดมินใหญ่** | มียศแอดมินใหญ่ หรือมีสิทธิ์ **Administrator** | ทุกหน้า |
| **ทีมงาน** | มียศทีมงาน | ทุกหน้า ยกเว้นหน้าตั้งค่า |
| คนอื่น | – | ❌ เข้าไม่ได้ |

คนที่ไม่ได้อยู่ในเซิร์ฟเวอร์ก็เข้าไม่ได้

### เปิดให้เข้าจากเครื่องอื่น

ค่าเริ่มต้นเปิดแค่ในเครื่องที่รัน ถ้าต้องการให้ทีมงานเข้าจากที่บ้าน:

1. เปลี่ยน `DASHBOARD_URL` เป็นโดเมนจริง เช่น `https://dash.example.com`
2. เพิ่ม Redirect URI ใหม่ใน Developer Portal ให้ตรงกัน
3. วางไว้หลัง reverse proxy ที่มี **HTTPS** (nginx / Cloudflare Tunnel)

> ⚠️ **ต้องใช้ HTTPS** ถ้าเปิดออกอินเทอร์เน็ต — session cookie ตั้ง `secure` อัตโนมัติเมื่อ `DASHBOARD_URL` เป็น `https://`
> ถ้าใช้ `http://` ออกเน็ต cookie จะถูกดักได้

### แก้ปัญหา

**❌ `Invalid OAuth2 redirect_uri`**

Redirect URI ใน Developer Portal ไม่ตรงกับ `DASHBOARD_URL` ใน `.env` — ต้องตรงทุกตัวอักษร รวม `http`/`https` และพอร์ต

**❌ พอร์ตถูกใช้แล้ว**

เปลี่ยน `DASHBOARD_PORT` ใน `.env` เป็นเลขอื่น (เช่น 3211, 4300) แล้วแก้ `DASHBOARD_URL` + Redirect URI ตามด้วย

**❌ ล็อกอินแล้วขึ้นว่า "ต้องเป็นทีมงานหรือแอดมินใหญ่"**

- ยังไม่ได้รัน `/setup-ticket` ในบอท (ระบบยังไม่รู้ว่ายศทีมงานคือยศไหน)
- หรือบัญชีที่ล็อกอินไม่มียศทีมงาน/แอดมิน

**ชื่อคนแสดงเป็นตัวเลข ID**

บอทดึงรายชื่อสมาชิกไม่ได้ — เปิด **SERVER MEMBERS INTENT** ใน Developer Portal → Bot

## 14. แก้ปัญหาที่พบบ่อย

### บอทรันไม่ได้

**❌ ไม่พบค่าที่จำเป็นในไฟล์ .env**

ยังไม่ได้สร้างไฟล์ `.env` หรือกรอกไม่ครบ

```bash
copy .env.example .env      # Windows
cp .env.example .env        # Mac/Linux
```

แล้วเปิดไฟล์กรอกให้ครบทั้ง 4 ค่า ดูขั้นตอนที่ [4. ตั้งค่าไฟล์ .env](#4-ตั้งค่าไฟล์-env)

---

**❌ TOKEN ไม่ถูกต้องหรือถูก reset ไปแล้ว**

Token ผิด หรือถูก reset ไปแล้ว (reset ครั้งใหม่ทำให้ token เก่าใช้ไม่ได้ทันที)

1. Developer Portal → เลือกแอป → **Bot** → **Reset Token**
2. คัดลอก token ใหม่ไปใส่ `.env` บรรทัด `TOKEN=`
3. รันบอทใหม่

⚠️ ตรวจว่าไม่มีช่องว่างหรือเครื่องหมายคำพูดครอบ token

---

**❌ บอทขอ intent ที่ยังไม่ได้เปิดใน Developer Portal**

ยังไม่ได้เปิด Privileged Intents

Developer Portal → **Bot** → **Privileged Gateway Intents** → เปิด:
- ✅ SERVER MEMBERS INTENT
- ✅ MESSAGE CONTENT INTENT

กด **Save Changes** แล้วรันบอทใหม่

---

**❌ เชื่อมต่อ Supabase ไม่ได้**

ตรวจตามลำดับนี้:

1. **`SUPABASE_URL` ถูกไหม** — ต้องเป็น `https://xxxxx.supabase.co` **ไม่มี `/` ปิดท้าย**
2. **ใช้ key ฝั่ง secret ไหม** — ต้องเป็น `sb_secret_...` หรือ `service_role` ถ้าใช้ `sb_publishable_...` / `anon` จะเชื่อมได้แต่อ่านข้อมูลไม่ได้ (RLS ปิดไว้)
3. **โปรเจกต์ Supabase ยังทำงานอยู่ไหม** — โปรเจกต์ฟรีจะถูก **pause อัตโนมัติหลังไม่ใช้ 7 วัน** เข้า Dashboard กด **Restore project**
4. **อินเทอร์เน็ตของเครื่องที่รันบอท**

---

**❌ เชื่อมต่อ Supabase ได้ แต่ยังไม่มีตาราง**

ยังไม่ได้รัน `schema.sql`

Supabase Dashboard → **SQL Editor** → **+ New query** → วางไฟล์ `schema.sql` ทั้งไฟล์ → **Run**

---

### คำสั่งไม่ขึ้นใน Discord

**พิมพ์ `/` แล้วไม่เห็นคำสั่งของบอท**

1. **รัน `npm run deploy` แล้วหรือยัง** — ต้องรันครั้งแรกเสมอ
2. **กด `Ctrl + R` ใน Discord** เพื่อรีเฟรช client
3. **ถ้าลงทะเบียนแบบ global** (ไม่ใส่ `GUILD_ID`) อาจรอถึง 1 ชั่วโมง
   → แก้เร็วๆ: ใส่ `GUILD_ID` ใน `.env` แล้วรัน `npm run deploy` อีกครั้ง คำสั่งจะขึ้นทันที
4. **เชิญบอทด้วย scope `applications.commands` ไหม** — ถ้าไม่ ต้องเชิญใหม่ด้วยลิงก์ที่ติ๊ก scope นี้

---

**❌ ลงทะเบียนไม่สำเร็จ: 404**

- **`CLIENT_ID` ผิด** — ต้องเป็น Application ID จากหน้า General Information
- **ใส่ `GUILD_ID` แต่บอทยังไม่ได้อยู่ในเซิร์ฟเวอร์นั้น** — เชิญบอทเข้าเซิร์ฟเวอร์ก่อน

---

### ระบบตั๋วมีปัญหา

**กดปุ่มเปิดตั๋วแล้วขึ้นว่าบอทสิทธิ์ไม่พอ**

Server Settings → **Roles** → เลือกยศของบอท → เปิด:
- ✅ Manage Channels
- ✅ Manage Roles

และ**ลากยศบอทขึ้นไปให้สูงกว่ายศทีมงาน**

ถ้ายังไม่ได้ ตรวจสิทธิ์ระดับ Category ด้วย: คลิกขวาที่ Category ห้องตั๋ว → Edit Category → Permissions → เพิ่มยศบอท → เปิด **View Channel** + **Manage Channels**

---

**"คุณมีตั๋วที่เปิดอยู่แล้ว" แต่หาห้องตั๋วไม่เจอ**

ปกติเกิดจากห้องถูกลบด้วยมือ ระบบจัดการให้เองอยู่แล้ว 3 ทาง:

1. **ตอนกดปุ่มเปิดตั๋ว** — บอทตรวจว่าห้องยังอยู่ไหม ถ้าไม่อยู่จะปิดตั๋วเก่าให้แล้วเปิดใบใหม่ทันที
2. **event `channelDelete`** — ห้องถูกลบตอนบอทออนไลน์ ระบบปิดตั๋วในฐานข้อมูลทันที
3. **ตอนบอทเริ่มทำงาน** — เก็บกวาดตั๋วที่ห้องหายไปตอนบอทออฟไลน์

ถ้ายังติดอยู่ ลองรีสตาร์ทบอทหนึ่งครั้ง

---

**ไม่ได้รับไฟล์ transcript ทาง DM**

Discord ไม่ยอมให้บอทส่ง DM ถ้าผู้ใช้ปิดรับ DM จากคนในเซิร์ฟเวอร์

เปิดรับ: **User Settings → Content & Social → Allow direct messages from server members**

ไม่ต้องห่วงข้อมูลหาย — บอทเก็บสำเนา transcript ไว้ใน**ห้องแผงควบคุม**ด้วยทุกครั้ง

---

### ระบบห้องเสียงมีปัญหา

**เข้าห้อง "➕ สร้างห้องของคุณ" แล้วไม่มีอะไรเกิดขึ้น**

1. **บอทออนไลน์อยู่ไหม** — ถ้าออฟไลน์ระบบจะไม่ทำงาน
2. **เปิด SERVER MEMBERS INTENT แล้วไหม** — ระบบห้องเสียงต้องใช้
3. **สิทธิ์บอท** — Server Settings → Roles → ยศบอท → เปิด **Manage Channels** + **Move Members** + **Connect**
4. **ดู log ในหน้าจอที่รันบอท** — จะมีข้อความบอกสาเหตุ เช่น `❌ [voice] สร้างห้องให้ ... ไม่สำเร็จ`
5. **รัน `/setup-voice` แล้วหรือยัง**

---

**ห้องเสียงว่างแล้วแต่ไม่ถูกลบ**

1. **บอทสิทธิ์ Manage Channels ในห้องนั้นไหม** — ดู log จะมี `⚠️ ลบห้อง ... ไม่ได้เพราะสิทธิ์ไม่พอ`
2. **บอทออฟไลน์ตอนคนออกจากห้อง** — ห้องจะถูกลบตอนบอทเริ่มทำงานครั้งถัดไป (รอบเก็บกวาด)
3. **ห้องถูกสร้างด้วยมือ ไม่ได้ผ่านบอท** — บอทลบเฉพาะห้องที่ตัวเองสร้าง (มีข้อมูลใน `temp_channels`)

---

**❌ ปุ่มนี้ใช้ได้เฉพาะเจ้าของห้อง**

1. ตรวจว่า**อยู่ในห้องเสียงของตัวเอง** ไม่ใช่ห้องคนอื่น
2. ถ้าเจ้าของเดิมออกไปแล้ว กดปุ่ม **🙋 ยึดห้อง** เพื่อยึดห้องก่อน
3. ถ้าอยู่ในห้องเสียงปกติของเซิร์ฟเวอร์ (ไม่ใช่ห้องชั่วคราว) แผงควบคุมใช้ไม่ได้

---

**❌ เปลี่ยนชื่อห้องบ่อยเกินไป**

Discord จำกัดการเปลี่ยนชื่อห้องไว้ที่ **2 ครั้งต่อ 10 นาที** ต่อห้อง เป็นข้อจำกัดของ Discord เอง แก้ไม่ได้ — ต้องรอ

---

## 📝 หมายเหตุ

- **ห้าม commit ไฟล์ `.env`** — มี Discord token และ Supabase secret key อยู่ (`.gitignore` กันไว้แล้ว)
- **โปรเจกต์ Supabase ฟรีจะ pause หลังไม่ใช้ 7 วัน** — เข้า Dashboard กด Restore เพื่อปลุก
- บอทเก็บกวาดข้อมูลค้างให้อัตโนมัติทุกครั้งที่เริ่มทำงาน ไม่ต้องดูแลฐานข้อมูลเอง
- ถ้า Supabase ล่มชั่วคราว บอทจะ retry ให้ 3 ครั้งพร้อม backoff และแจ้งผู้ใช้เป็นภาษาไทยถ้ายังไม่สำเร็จ — บอทไม่ crash
